# PLAN

Roadmap for `algo-transcribe`. This file lists open work only. Each checkbox is
one pull request and is written to be picked up by a headless session
(ccbatch): the task text is the whole first paragraph of the item, so it stays
self-contained. Everything technical refers to
[docs/port-spec.md](docs/port-spec.md).

When an item is done, tick it and append a one-line note: what was covered, the
resulting numbers (tolerances reached, benchmark figures), and any deliberate
gap.

## Dependencies and sequencing

```
B1: 1.1, 1.2, 1.3          (independent, run in parallel)
B2: 2.1, 2.2, 2.3          (need B1 merged; 2.1 also needs algo-dsp v0.13.0, the first tag with dsp/cqt)
B3: 3.1                    (needs B2 merged and github.com/cwbudde/midi with Track.PitchBend tagged)
P:  4.1 → 4.2              (independent of B2/B3; may land before or after v0.1.0; 4.2 after 4.1 merges)
→ tag v0.1.0, then the editor integrates it (algo-audio-editor PLAN Phase 35)
```

- [ ] 2.1 `frontend` — Implement the basic-pitch front end in package `basicpitch`: padding by 3840 samples, windows of 43844 at hop 36164 with zero-padded tail, and `unwrap` (drop 15 frames per side, trim to the v0.4.0 rule `floor(len*86/22050)` of the original length, not the later `main` rule `int(len/36164*142)`; the fixtures have 430/344 frames) exactly as docs/port-spec.md §2; the CQT (§3.1) via `github.com/cwbudde/algo-dsp/dsp/cqt` at v0.13.0 (no pseudo-versions), built as `cqt.New(cqt.BasicPitchSampleRate, cqt.BasicPitch()...)`: the preset sets hop 256, fmin 27.5 Hz, 309 bins at 36 per octave, L1 basis norm, periodic Hann, reflect padding (`WithCenter(cqt.PadReflect)`), librosa normalization, magnitude output and nnAudio's quirks, so add no options of your own; check `FrameCount(43844) == 172` and `Bins() == 309`, and use the `cqt.BasicPitch*` constants instead of literals; NormalizedLog per window (§3.2); the folded BatchNorm with constants from the embedded weights (§3.3); harmonic stacking (§3.4). Cross-check the algo-dsp CQT kernels, low-pass and sqrt-length factors against the ONNX constants from 1.2 (≤1e-6). Parity against the 1.3 fixtures for every window of both clips: CQT ≤1e-4 relative, NormalizedLog/BN and harmonic stack ≤1e-4 absolute. algo-dsp's CQT checks are now Go-only (its item 46.4), so this parity is the only check of the preset against basic-pitch's own graph. Make the stages after the CQT resumable in bounded units and benchmark the unit cost; the CQT itself runs as one `ProcessInto` call per window here (about 6 ms native), and the bounded `cqt.Stepper` from algo-dsp item 46.6 replaces it in 3.1's `Job`. If algo-dsp's CQT cannot reach the tolerance, report the measured gap and the cause instead of loosening it.

Benchmarks (`docs/benchmarks/2026-10-10-model.md`, Apple M5 Pro, Go 1.27.1, Node 24, medians): full window 38.6 ms native (42.5× realtime) and 96.3 ms js/wasm (17.0×). - [x] 2.3 `notes` — Port `basic_pitch/note_creation.py` verbatim into package `basicpitch`: `constrain_frequency`, `get_infered_onsets`, `argrelmax` peak picking with its ordering, the onset pass, the melodia pass with its different end offset, amplitudes, `get_pitch_bends` (Gaussian window), `model_frames_to_time` with the 172-frame floor quirk, and `drop_overlapping_pitch_bends`. Follow docs/port-spec.md §5 and the upstream file line by line; keep float32/float64 choices identical to NumPy's where they affect comparisons. Input is the fixture unwrapped model outputs from 1.3; the output must match the fixture note events **exactly** (same count, order, start/end frames, pitches, amplitudes to float32 precision, bends) for every option variant. Add table tests for edge cases (empty input, all-silent frames, notes touching the first/last frame, NaN in the onset rescale).
  - Done. `basicpitch/notes.go` (`noteDecoder.decode`: constrain, inferred onsets, `argrelmax` peaks, onset and melodia passes, amplitudes) and `basicpitch/notes_bends.go` (`get_pitch_bends`, `model_frames_to_time`, `drop_overlapping_pitch_bends`), composed as `modelOutputToNotes`. Everything is unexported; 3.1 builds the API. All 10 clip/variant pairs match exactly: count, order, frames, pitches, amplitude bits, 6,771 synth and 710 vocal bends, the seconds (bit for bit) and the sorted, overlap-dropped MIDI note order. This holds natively and under js/wasm. There are 30 edge cases, with expectations taken from upstream run in a scratch NumPy 2.5.3 env, and a scratch-only random cross-check of 60 inputs and 126,721 notes. Melodia keeps a per-row max cache in a tournament tree instead of rescanning the matrix (exactly NumPy's flattened first argmax). A warm decoder does 0 allocs. Decoding takes 0.32 ms for synth (430 frames, 21 notes) and 20.1 ms for a synthetic 3-minute input (15,500 frames, 1,491 notes). Measured 2026-10-10 on an Apple M5 Pro with Go 1.27.1, median of 5. **Discoveries** (port-spec §5/§7):
    - `np.mean` of float32 is a float32 _pairwise_ sum; a float64 or sequential sum misses dozens of amplitudes.
    - `velocity` is a float32 product (60 float32 amplitudes round differently in float64; no fixture note hits one).
    - Silent or constant frames make the inferred onsets all NaN (0/0), so there are no onset notes.
    - `onset_thresh <= 0` makes every non-peak cell an onset.
    - The frequency bounds use Python slice semantics (10 Hz zeroes the top 18 bins).
    - A NaN in the remaining energy ends melodia.
    - With melodia, `frame_thresh < 0` never terminates (Go returns an error); `min_note_len < 0` emits NaN zero-length notes.
    - Go's exact constant arithmetic puts `window_offset` one ulp off, and arm64 FMA fusion can do the same, so the port uses typed steps.
    - The Gaussian window is hard-coded from SciPy.
      **Deliberate deviations:** empty input returns no notes, where upstream raises. A frequency of 0 means None. **Gaps:** note creation runs as one call; at 20 ms for 3 minutes it must become resumable for the 3.1 `Job`. NumPy might chunk sums over notes longer than 8,192 frames (95 s), which is not reproduced. The synth clip keeps no bends after the overlap drop, so only vocal and the synthetic tests cover kept bends.

## Phase 4: Native SIMD GEMM (P)

wasm stays on the Go tiles: Go emits no wasm SIMD, and js/wasm is the primary target, so nothing here may slow it down. These items supersede 1.1's "no assembly" for native arm64 and amd64 only.

- [ ] 4.1 `gemm-neon` — Add arm64 NEON Plan 9 assembly kernels for `nn`'s GEMM, following algo-fft's pattern (`internal/asm/arm64/neon_complex_mul.s`, `internal/fft/complex_mul*.go`, and the "When Working with Assembly" section of its AGENTS.md): `nn/gemm_arm64.s` plus `nn/gemm_arm64.go` (`//go:build arm64 && !purego`) with `//go:noescape` declarations and a wrapper `gemmSIMD(out, a, wt, bias []float32, m, k int) bool` that `gemm` tries first; the existing Go tiles become the fallback, built under `!arm64 || purego`, so js/wasm and other targets compile exactly the code they do today. NEON is mandatory on arm64, so there is no runtime detection. Cover the multi-channel case (N a multiple of 4; basic-pitch has N = 8 and 32) and the single-channel N = 1 case (contours-reduced, conv2d_3, conv2d_5); any shape a kernel does not cover falls back to the Go tiles. Choose the data layout and justify it in the PR with measurements: either the dot form over the current Bᵀ layout `wt[co*k+i]` (k-vectorised accumulators, horizontal reduction at the end), or an outer-product form with by-element `FMLA` over the HWIO k×N weights packed once in `NewConv2D`; zero-padding k to a multiple of 4 or 8 in both `col` and `wt` to remove asm tails is allowed, as long as nothing allocates after setup. Use `VFMLA … .S4`; where Go's arm64 assembler lacks a vector float mnemonic, copy the WORD-encoded macros from algo-fft's `internal/asm/arm64/neon_fp.h` with attribution. Each `gemm` call covers at most `blockM = 8` rows, and `ForwardRows` chunking only splits output rows, so the kernel must be deterministic per call but need not reproduce the scalar summation order. Tests: extend `TestGemmTiled` so the SIMD path and every Go tile (nr 4 and 2) are checked against the float64 reference with the existing tolerance over k ∈ {1, 2, 3, 5, 8, 49, 200, 297, 672, 936}, m 0–17 and n 1–9 plus 32, with a guard element after the output; add a direct SIMD-vs-Go comparison and a test that the SIMD path is actually taken on arm64 for every basic-pitch layer shape. `TestConv2DForwardRowsChunking` (bit-identical), `TestConv2DZeroAllocs` and the model parity (≤1e-4 against the fixtures) must pass natively, and `go test -tags purego ./...` and `just test-wasm` must pass unchanged. CI: add `macos-latest` (arm64) to `.github/workflows/test-unit.yml`, a `-tags purego` test step, and `go vet` for `GOARCH=arm64` and `GOARCH=amd64` so asmdecl checks the frames. Add an "Assembly" section to AGENTS.md adapted from algo-fft's (Plan 9 operand order, `NOSPLIT` and argument frame sizes, `go:noescape`, always a Go fallback, every asm entry point called by a test, wasm must not regress), and update the `gemm` doc comment, `nn/doc.go` and the README performance figures. Benchmarks: per basic-pitch layer and the full window, Go tiles (`-tags purego`) versus NEON, native arm64, plus js/wasm to show it is unchanged; record ns/op and GMAC/s with date, CPU, Go version and method in `docs/benchmarks/<date>-simd-gemm.md`. Acceptance: the full window is measurably faster, and on every basic-pitch layer shape the SIMD path is at least as fast as the Go tile; where it is not, dispatch falls back for that shape and the PR says so. Report the measured speedup rather than a target.
