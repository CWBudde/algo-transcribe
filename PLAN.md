# PLAN

Roadmap for `algo-transcribe`. This file lists open work only. Each checkbox is
one pull request and is written to be picked up by a headless session
(ccbatch): the task text is the whole first paragraph of the item, so it stays
self-contained. Everything technical refers to
[docs/port-spec.md](docs/port-spec.md).

When an item is done, tick it and append a one-line note: what was covered, the
resulting numbers (tolerances reached, benchmark figures), and any deliberate
gap.

## Dependencies and sequencing

```
B1: 1.1, 1.2, 1.3          (independent, run in parallel)
B2: 2.1, 2.2, 2.3          (need B1 merged; 2.1 also needs algo-dsp with dsp/cqt tagged)
B3: 3.1                    (needs B2 merged and github.com/cwbudde/midi with Track.PitchBend tagged)
→ tag v0.1.0, then the editor integrates it (algo-audio-editor PLAN Phase 35)
```

## Phase 1: Foundations (B1)

- [ ] 1.1 `nn` — Create package `nn`, a minimal float32 inference library with NHWC tensors (plain `[]float32` plus shape; no generic tensor framework). Implement `Conv2D` with TensorFlow `padding="same"` semantics, including the asymmetric frequency padding under stride 3 (docs/port-spec.md §4), arbitrary (h,w) strides, weights in HWIO layout and a bias. Build it as im2col plus a blocked float32 GEMM written for the compiler (no assembly; it must stay fast under js/wasm). Make it row-steppable: compute output rows `[r0, r1)` so callers can bound the work per step (AGENTS.md rule 4). Also add in-place ReLU and sigmoid, channel concat, and a helper that folds inference BatchNorm (gamma, beta, mean, variance, epsilon) into conv weights and bias. Tests: table-driven against a naive direct-convolution reference over kernel sizes, strides and padding edge cases; the exact layer shapes of basic-pitch (§4 table); zero allocations after setup. Benchmarks per basic-pitch layer shape for a full 172-row window, native and under `just test-wasm` style execution; record ns/op and MAC/s in the PR body. Add `Example`s.
- [ ] 1.2 `weights` — Extract the basic-pitch weights. Download upstream `basic_pitch/saved_models/icassp_2022/nmp.onnx` (basic-pitch v0.4.0) into `testdata/nmp.onnx`, record its SHA-256 and source URL in `testdata/README.md` (Apache-2.0, Spotify; NOTICE already covers it). Write a dependency-free ONNX protobuf reader in `internal/onnx` (varint/length-delimited walk over `ModelProto.graph`: `initializer` TensorProto with dims, data_type and raw_data or float_data; `node` with op_type, inputs, outputs and attributes) with unit tests on hand-built messages. Write the generator `internal/cmd/extractweights` (invoked by a `go:generate` line in package `basicpitch`) that maps the six Conv nodes to the layers of docs/port-spec.md §4 by following node inputs (never by initializer order), converts OIHW to HWIO, and writes `basicpitch/weights.bin` (little-endian float32) plus `basicpitch/weights.go` with a manifest (layer name, shape, offset, length) and an embed loader. Also export the CQT real/imag kernels, the low-pass filter, the sqrt-length factors and the CQT BatchNorm scale/offset as named tensors for cross-checks. Tests: every shape matches §4, the total parameter count is 16,782 plus the front-end constants, the ONNX SHA-256 matches, and regenerating produces a byte-identical `weights.bin`. Document in port-spec.md anything in the ONNX graph that differs from §3/§4.
- [ ] 1.3 `fixtures` — Create the golden-data generator `scripts/fixtures/` as a `uv` project (`pyproject.toml` with exact pins: basic-pitch 0.4.0, onnxruntime, numpy, scipy, librosa, pretty_midi; a `uv.lock`) with `generate.py`, run via `just fixtures`. Inputs, both mono 22050 Hz so no resampling is involved: (a) a deterministic synthetic polyphonic clip of about 5 s generated in the script (overlapping chords of harmonic tones with decaying envelopes, one note with a slow pitch glide, some silence), and (b) the first ~4 s of `test_data/vocal-da-80bpm.22050.wav` from spotify/basic-pitch-ts (Apache-2.0; credit in testdata README). For each clip dump, using the ONNX model through onnxruntime and intermediate graph outputs where needed (onnxruntime can expose intermediate tensors by adding graph outputs; alternatively recompute the front end in NumPy and assert it matches the model): the windowed audio, per-window CQT magnitude (172×309), NormalizedLog output, CQT after BatchNorm, harmonic stack (172×264×8), and the contour/note/onset outputs; the unwrapped outputs after `unwrap_output`; note events from `output_to_notes_polyphonic` for the default options and for variants `melodia_trick=False`, `infer_onsets=False`, `minimum_frequency=100,maximum_frequency=1000`, `onset_threshold=0.3,frame_threshold=0.2`; pitch bends; the frame times; and the pretty_midi note list and CSV that upstream would write. Format: little-endian `.f32` files plus one `manifest.json` per clip (shapes, dtypes, options, upstream version); notes as plain JSON. Keep `testdata/` under ~5 MB in total (gzip large `.f32`). Add the Go loader `internal/fixture` with tests that load every file and check shapes. Document regeneration in `scripts/fixtures/README.md`.

## Phase 2: Port (B2)

- [ ] 2.1 `frontend` — Implement the basic-pitch front end in package `basicpitch`: padding by 3840 samples, windows of 43844 at hop 36164 with zero-padded tail, and `unwrap` (drop 15 frames per side, trim to `int(len/36164*142)`) exactly as docs/port-spec.md §2; the CQT via `github.com/cwbudde/algo-dsp/dsp/cqt` configured as §3.1 (bump algo-dsp to the release that contains it; no pseudo-versions); NormalizedLog per window (§3.2); the folded BatchNorm with constants from the embedded weights (§3.3); harmonic stacking (§3.4). Cross-check the algo-dsp CQT kernels, low-pass and sqrt-length factors against the ONNX constants from 1.2 (≤1e-6). Parity against the 1.3 fixtures for every window of both clips: CQT ≤1e-4 relative, NormalizedLog/BN and harmonic stack ≤1e-4 absolute. Make the per-window work resumable in bounded units (for example one CQT octave per unit) and benchmark the unit cost. If algo-dsp's CQT cannot reach the tolerance, report the measured gap and the cause instead of loosening it.
- [ ] 2.2 `model` — Implement the CNN graph of docs/port-spec.md §4 on package `nn` with the embedded weights from 1.2: `Model.Forward(stack) (contour, note, onset)` for one window, plus a resumable `ForwardJob` that advances layer by layer and row block by row block so one step stays bounded (target ≤1 ms native on an Apple M-series or comparable laptop). Parity: feed the fixture harmonic stack of every window and compare contour, note and onset to the onnxruntime outputs at ≤1e-4 absolute. Benchmarks: a full window and the largest single step, native and under js/wasm in Node; record realtime factor (window covers 36164/22050 s of new audio) in `docs/benchmarks/` with date, CPU and method.
- [ ] 2.3 `notes` — Port `basic_pitch/note_creation.py` verbatim into package `basicpitch`: `constrain_frequency`, `get_infered_onsets`, `argrelmax` peak picking with its ordering, the onset pass, the melodia pass with its different end offset, amplitudes, `get_pitch_bends` (Gaussian window), `model_frames_to_time` with the 172-frame floor quirk, and `drop_overlapping_pitch_bends`. Follow docs/port-spec.md §5 and the upstream file line by line; keep float32/float64 choices identical to NumPy's where they affect comparisons. Input is the fixture unwrapped model outputs from 1.3; the output must match the fixture note events **exactly** (same count, order, start/end frames, pitches, amplitudes to float32 precision, bends) for every option variant. Add table tests for edge cases (empty input, all-silent frames, notes touching the first/last frame, NaN in the onset rescale).

## Phase 3: Public API (B3)

- [ ] 3.1 `api` — Assemble the public API in `basicpitch`: `Options` (onset/frame thresholds, minimum note length in ms, min/max frequency, infer onsets, melodia trick, include pitch bends, multiple pitch bends, MIDI tempo; zero value means upstream defaults), `Transcribe(ctx, mono []float32, sampleRate float64, opts Options) (*Result, error)` with `Result{Notes []Note; Activations}` where `Note` holds start/end seconds, MIDI pitch, amplitude and bends. Input at any sample rate is resampled to 22050 with `github.com/cwbudde/algo-dsp/dsp/resample`. Add the resumable `Job` (`NewJob(sampleRate, opts)`, `Feed(samples)`, `Close()`, `Step() (done bool, err error)`, `Progress() (done, total int)`, `Result()`), whose every step is bounded (benchmark-guarded, ≤1 ms native), and `Renote(opts)` that reruns note creation on cached activations without inference. Add package `smfout`: MIDI through `github.com/cwbudde/midi/smf` (bump to the release with `Track.PitchBend`) reproducing pretty_midi semantics of docs/port-spec.md §5 in seconds at 120 BPM, and CSV identical to upstream `note_events_to_csv`. Add `cmd/algo-transcribe` (WAV in via `github.com/cwbudde/wav`, `-o` with `.mid`, `.csv` or `.json` out, flags for every option). Tests: end-to-end on both fixture clips (identical pitches, onsets/offsets within ±1 frame), MIDI and CSV against the fixture pretty_midi output, a 44.1 kHz input checked at note level, context cancellation, and `Job` vs `Transcribe` equivalence. Update README usage, add `Example`s, write the CHANGELOG section for v0.1.0 and record native and wasm realtime factors in `docs/benchmarks/`.
